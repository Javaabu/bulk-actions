# bulk-actions: notes for AI coding agents

`javaabu/bulk-actions` is a Laravel package: bulk action definitions (`BulkActions`, `Action`), authorized through the Gate, with stencil forms, chunked and queued execution, and the UI in Blade (javaabu/forms v2) and Inertia React (`resources/js`, imported by apps as `@javaabu/bulk-actions` through javaabu/manifest). A prebuilt Blade script ships in `dist/`.

## Layout

| Path | What |
| --- | --- |
| `src/BulkActions.php` | The set: actions, model, query, filters, user, execution, output (`toArray()`, `render()`) |
| `src/Actions/` | `Action` (presentation, `can()`/`canEach()`, form, handlers, chunking, queueing) and the built-ins |
| `src/Execution/` | `Executor` (validate, authorize, run or queue, respond), `Runner` (chunks), `Selection`, `ActionResult` |
| `src/Models`, `src/Jobs`, `src/Enums`, `src/Events`, `src/Policies` | Queued runs |
| `src/Http`, `src/Routing` | Controllers and the `Route::bulkActions()` / `Route::bulkActionRuns()` macros |
| `src/Support/FiltersAdapter.php` | javaabu/filters, duck-typed: it's optional, so never reference its classes in `src/` |
| `src/Views/Components/Actions.php`, `resources/views/actions.blade.php` | `<x-bulk-actions::actions>` |
| `resources/js/` | React components (`BulkActions.tsx`), `types.ts` (the JSON from `toArray()`), `support.ts`, and `blade/bulk-actions.ts` (the Blade script) |
| `dist/` | The Blade script, built and **committed**. CI fails if it's stale |
| `tests/` | PHPUnit (`Unit`, `Feature`, `Fixtures`) and Vitest (`tests/js`, with fixtures generated by `JsFixtureTest`) |
| `docs`, `llms.txt`, `resources/boost` | Docs, the index for assistants, the Laravel Boost guideline and skill |

## Rules

- Follow the Javaabu PHP guidelines (`vendor/javaabu/boost-javaabu-guidelines`): snake_case variables and properties, camelCase methods, `#[Test]` methods named `it_…`, early returns, no `else`.
- A change to `toArray()` changes `resources/js/types.ts`, `docs/advanced-usage/api-reference.md` and the components together. Then run `BULK_ACTIONS_UPDATE_FIXTURES=1 vendor/bin/phpunit --filter JsFixtureTest` and commit `tests/js/fixtures`. The same goes for the Blade view's markup.
- After changing `resources/js/blade` or `resources/js/support.ts`, run `pnpm build` and commit `dist/`.
- javaabu/filters is optional: CI runs the suite without it. Its tests skip themselves when it's missing.
- Every user-facing string goes in `lang/en` and `lang/dv` (same keys, placeholders and plural forms; `LocalizationTest` checks). Views use logical directions only.
- Every change needs tests, docs (linked from `llms.txt`), the Boost skill if it changes usage, and a line in `CHANGELOG.md`.

## Commands

```bash
composer install && pnpm install      # pnpm 10.28 (packageManager)
composer lint && composer test        # Pint and PHPUnit
pnpm lint && pnpm format:check && pnpm typecheck && pnpm test
pnpm build                            # dist/
```
